## 🎯 Твоя задача:
Ты — главный клей и контролер качества проекта. Ты соединяешь климатические данные Backend 1 с алгоритмами севооборота Backend 2 и передаешь их на интерфейс Frontend Lead, фиксишь баги и гарантируешь 100% стабильность на защите.

### 1. Файлы, с которыми ты работаешь:
* ✏️ `modules/fieldshift_facade.py` — функция-связка `get_fieldshift_recommendation()`.
* ✏️ `tests/test_fieldshift_integration.py` — интеграционные тесты сквозного пайплайна.
* ✏️ Контроль чистоты `dashboard/app.py` и `PROJECT_STATE.md`.

## 📋 Чек-лист шагов:

- [ ] **Шаг 1. Контроль соблюдения контракта (Часы 0–4):**
  - Убедиться, что Backend 1, Backend 2 и Frontend Lead поняли `00_CONTRACT.md`.
  - Предоставить мок-генератор для фронтендера на время разработки.
- [ ] **Шаг 2. Создание функции-фасада `modules/fieldshift_facade.py`:**
  - Принимает словарь с фронтенда (регион, почва, веса слайдеров).
  - Запрашивает климатические данные NASA у модуля Backend 1 (`get_nasa_climate_summary`).
  - Передает их в агро-движок Backend 2 (`CropRotationEngine`).
  - Возвращает финальный JSON-ответ фронтендеру.
- [ ] **Шаг 3. Замена мок-данных во фронтенде на реальный бэкенд:**
  - Помочь фронтендеру подключить вызов `get_fieldshift_recommendation()` в `dashboard/rotation_planner_tab.py`.
- [ ] **Шаг 4. Оффлайн-проверка (Fail-Safe для защиты):**
  - Отключить Wi-Fi / сеть на тестовой машине.
  - Убедиться, что дашборд продолжает работать на локальном кэше без крашей и ошибок.
- [ ] **Шаг 5. Стресс-тестирование крайних случаев (Edge Cases):**
  - Проверить нулевые веса слайдеров ($0, 0, 0, 0$).
  - Проверить экстремальные площади (0.1 га и 50 000 га).
  - Проверить смену всех типов почв. Никаких unhandled exceptions!
- [ ] **Шаг 6. Запуск полного регрессионного тестирования:**
  - В отдельном hackathon-репозитории: `python -m unittest discover -s tests -v` (и новые интеграционные тесты).
  - Если работаете в monorepo AgriCascade: дополнительно `python tests/run_all_daryn_tests.py` — старые тесты не должны сломаться.
